The five things that matter most

  1. The CRM is publicly readable and writable right now. Row-level security was switched off on people and inquiries in migration 029 and never turned back on. I confirmed it: a request with the anon key from the JS bundle returns rows from both tables in production. Anyone can dump every contact's name, email, phone and birth data, delete the CRM, or plant script in a contact name (SEC-02).
  2. Any member can promote themselves to admin. The profiles update policy has no column restriction, and every admin gate in the app trusts profiles.role. One PATCH call turns a free signup into an account that can refund, impersonate astrologers and broadcast to the whole list (SEC-01).
  3. Stored XSS has three live paths and no safety net. The public blog renders DB markdown with marked and no sanitizer even though a sanitizer already exists in the repo; guest-typed names and questions are inserted as raw HTML on the staff reading page; LLM-generated reading HTML is shown raw on the public reading link. There is no Content-Security-Policy and the session cookie is JS-readable, so any of these is an account takeover (SEC-03, SEC-04, SEC-05, SEC-08).
  4. Phones have no navigation. At 768px and below the nav hides every link and nothing replaces them: no hamburger, no member menu, no sign-out. Four layouts are also truly broken at 375px (card pages scroll sideways, the Purple Star chart is unreadable, two admin tables overflow, horoscope tabs spill), and every form zooms on iOS because inputs are under 16px (MOB-01 to MOB-06).
  5. Three design systems are fighting in one app. The Revenue admin still runs Edge8's blue palette and an unloaded font (primary button is red at rest, blue on hover). The almanac and horoscope components reference tokens that do not exist and fall back to a cream palette. The core tokens themselves fail WCAG contrast: --ink-4 for all captions is 3.28:1, white on the brand red is 4.31:1, and prose links are colour-only at 2.46:1. 577 hard-coded hex values and 472 inline styles keep the drift going (UI-01 to UI-08).

What is in good shape

  • The App Router code is guarded well: every server action calls requirePermission, every cron route enforces the CRON_SECRET bearer, Stripe and Resend webhooks verify signatures with replay protection, unsubscribe tokens are HMAC-signed and compared in constant time. No secrets in tracked files or git history.
  • The Revenue admin (app/admin/revenue) is already mobile-ready: scrolling tables and calendars, 44px touch targets on coarse pointers, a 94vw drawer.
  • Public pages all use next/image, every icon-only button has an aria-label, and the member shell, signup, booking steps, blog body and footer scale down correctly.

Plan at a glance

Phase 1 · Stop the bleeding (security, same day)

Migrations to re-enable RLS on people/inquiries with portal-user policies and to lock profiles.role/person_id behind a trigger; sanitize the three HTML render paths; escape JSON-LD; add security headers; per-astrologer ownership checks; booking hold/payment fixes; LIKE escaping and email validation; constant-time secret compares; generic error messages; remove dead Brevo endpoints.

Phase 2 · Make phones work

Mobile menu in Nav; collapse the card-page grid, Purple Star chart and calendar grids; wrap admin tables; 16px inputs on phones; 44px touch targets; reduce desktop padding and stacked section spacing; show (not hide) hero images; blog table styling; sizes on fill images; viewport meta; reduced-motion rule.

Phase 3 · One design system

Repoint the Revenue admin tokens to the fire scale and loaded fonts; fix contrast at the token level (--ink-4, CTA fill, prose links); map the almanac/horoscope --color-* fallbacks to real tokens; kill the v1.0 red; consolidate buttons, inputs, cards, error and tone scales onto globals; single blog category source; blog post social meta; move inline styles and hex literals to modules and tokens; dedupe blog block CSS; prune Edge8-only admin CSS; align the style guide with what is built.

Phase 4 · Verify and ship

next build must pass; anon-key probe of people/inquiries must return nothing; admin pages still load for staff; mobile pages checked at 375px in the browser; one PR to main, Vercel deploys.

Not fixed without a business decision: SEC-11 (whether the member area is meant to be free or subscription-gated) and whether the session cookie can move to httpOnly (it would require moving auth to a server-side flow). Both are documented and left as-is.
